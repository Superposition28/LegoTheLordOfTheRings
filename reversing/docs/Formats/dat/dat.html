Binary Layout: Archive Footer, Header, and TOC Structures

DAT / HDR Root Header & Entry Records (Little-Endian TOC)
Region / Offset Size Type Field Description
DAT+0x00 4 u32le toc_ptr (offset >> 8) | 0x80000000 in MkDat/PakDat, or negative-signed i32le TOC sector/byte offset.
DAT+0x04 4 u32le toc_size Total byte length of embedded TOC block (zero or absent when external .HDR holds TOC).
HDR+0x00 4 / 4 u32le / i32le toc_size, toc_ver Paired .HDR stores TOC byte size then negative TOC version (-5, -7); full TOC follows immediately.
TOC+0x00 8 i32le[2] toc_ver, file_count Negative version (-1..-7) followed by file_count.
Entry[i] (16 B) 4,4,4,4 u32le[4] off_packed, comp_sz, uncomp_sz, meta For v-1..-4: offset = off_packed * 0x100, meta holds compression ID (low bits) & optional chunk flags.
Entry[i] (v-5..v-7) 16 B u32le[4] offset256, comp_sz, uncomp_sz, meta Expanded volume index & codec bits in meta (comp_type = (meta & 0xFF) or chunk bitmask); block size 256 B (<< 8).
Node[k] (8B / 12B) 8 or 12 i16,i16,u32[,u16,i16] next, child_or_sib, name_off[, parent, entry_idx] Directory trie. 8B infers parent from prev_sib == 0 ? k-1 : parent[prev_sib]; 12B adds explicit parent and entry_idx.
Tail Hashes 4 * file_count u32le[] path_hashes Uppercase FNV1a-32 of every path (TtPathHash). Note: TCS PC Steam stores ascending values (0x3c27d..) here instead.

Compression & Hashing Formulas

  • TtPathHash(path): Start h = 0x811C9DC5. Replace '/' with '\\', ASCII-uppercase each byte c, iterate h = ((h ^ c) * 0x00199933) & 0xFFFFFFFF. Matches 100% of PS3/X360 entries across v-2..v-5 and 124,712/124,716 in Dimensions v-7.
  • DFLT (Codec 3): Series of 12-byte chunk headers ("DFLT", u32le comp_sz, u32le uncomp_sz). If standard raw RFC 1951 Deflate fails, toggle bit 2 of the first payload byte (payload[0] ^= 0x04) before inflating.
  • ZIPX (Codec 6/RC4): 12-byte header ("ZIPX", u32le comp_sz, u32le data_sz). Payload is encrypted with RC4 using the 4-byte little-endian representation of data_sz as the symmetric key!
  • LZ2K (Codec 2): 12-byte header ("LZ2K", u32le uncomp_sz, u32le comp_sz). Uses dynamic 2-table Huffman + 8 KiB sliding ring buffer (0x2000, pos_mask = 0x1FFF). If comp_sz == uncomp_sz, copy raw payload.

Cross-Format Relationships & Dependencies

Referenced By (Upstream Containers / Loaders)

  • EBOOT.BIN / .xex / .exe — Mounts GAME*.DAT/.HDR volumes and resolves asset requests by FNV1a path hash.
  • PS3 .pkg / INSTALL0*.DAT — DLC packages and CMP2 LZMA install volumes deliver extra GAME*.DAT/.HDR patches.

References (Downstream Assets / Sub-Formats)

  • .gsc / .ghg Models — Primary level & character geometry archives stored inside .DAT.
  • .edfile (.cd/.cpd/.as/.apj/.led) — Reflected scene/character graphs referencing assets within the same mounted .DAT tree.
  • .res Resource Manifests — Era 4 NuFileTree dependency lists indexing virtual .DAT paths.
  • .pak / .pac Sub-Archives — Secondary uncompressed asset bundles packed inside .DAT.

Filtering, Edge Cases & Unresolved Fields

  • TCS WinSteam Hash Anomaly (Unresolved): GAME.DAT (v-3, 12,174 entries) stores strictly ascending 32-bit values (0x3c27d, 0x51307, 0x98a59...) in the hash table instead of FNV1a-32; the exact hash/key polynomial used by that PC Steam build remains unresolved.
  • Dimensions 4 Non-Matching Hashes: 4 of 124,716 entries in LEGO Dimensions exhibit root/trailing separator quirks in path reconstruction.
  • Empty Padding Files: PAD.DAT (up to 15.36 GB in Hobbit) contains only physical disc LBA padding and has no TOC entries.
  • Mixed Offset Units in .HDR/v-5..v-7: Offsets multiply by 256-byte sector alignment (offset << 8) except inside CMP2-unpacked volumes where byte offsets apply directly.

Standalone Clean-Room Parser Pseudocode

function TtPathHash(path):
    h = 0x811C9DC5
    for ch in path:
        c = ord('\') if ch == '/' else ord(ch.upper())
        h = ((h ^ c) * 0x00199933) & 0xFFFFFFFF
    return h

function ParseDatOrHdr(dat_stream, hdr_bytes=null):
    if hdr_bytes != null:
        toc_size, neg_ver = ReadI32LE2(hdr_bytes, 0)
        toc = hdr_bytes[4 : 4 + toc_size]
    else:
        raw0, toc_size = ReadU32LE2(dat_stream, 0)
        toc_off = raw0 & 0x7FFFFFFF
        toc = dat_stream.ReadAt(toc_off, toc_size)
    ver = ReadI32LE(toc, 0); file_count = ReadU32LE(toc, 4); pos = 8
    entries = []
    for i in 0 .. file_count - 1:
        off_raw, csz, usz, meta = ReadU32LE4(toc, pos); pos += 16
        entries.append({off: off_raw * 256, csz: csz, usz: usz, meta: meta})
    node_count = ReadU32LE(toc, pos); pos += 4
    node_size = 8 if ver >= -4 else 12
    nodes = [ReadNode(toc, pos + k * node_size, node_size) for k in 0 .. node_count - 1]
    pos += node_count * node_size
    str_len = ReadU32LE(toc, pos); str_buf = toc[pos + 4 : pos + 4 + str_len]
    ReconstructPathsFromTrie(entries, nodes, str_buf, node_size)
    return entries

function DecompressEntry(raw, codec, usz):
    if codec == 0: return raw[:usz]
    if codec == 2: return DecompressLZ2KChunks(raw)
    if codec == 3:
        out = []
        p = 0
        while p + 12 <= len(raw) and raw[p:p+4] == "DFLT":
            csz, chunk_u = ReadU32LE2(raw, p + 4); pay = raw[p+12 : p+12+csz]; p += 12 + csz
            if csz == chunk_u: out.append(pay)
            else: out.append(TryRawInflate(pay) or TryRawInflate(ToggleBit2Byte0(pay)))
        return Concat(out)
    if codec == 6: return RC4DecryptZIPXChunks(raw)
